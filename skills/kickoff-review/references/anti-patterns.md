# 착수보고서 안티패턴 사전

착수보고서에서 자주 발견되는 문제 패턴. 각 유형별 탐지 방법과 개선 제안을 포함한다.

---

## 유형 1. 모호한 표현 (Vague Language)

### 자동 탐지 대상 단어/구문

| 패턴 | 예시 | 문제 |
|------|------|------|
| "적절히", "적절한" | "적절히 처리한다" | 기준 없음 |
| "필요 시", "필요에 따라" | "필요 시 확장한다" | 트리거 조건 미정 |
| "등", "기타" | "결제, 정산 등" | 범위 불명확 |
| "가능한 한", "최대한" | "가능한 한 빠르게" | 측정 불가 |
| "협의 예정", "추후 결정" | "일정은 추후 결정" | 미확정 항목 방치 |
| "검토 중", "검토 예정" | "아키텍처 검토 중" | 의사결정 지연 |
| "유사한", "비슷한" | "유사한 시스템 참고" | 참조 기준 불명확 |
| "충분한", "적절한 수준" | "충분한 성능" | 수치 없음 |
| "지속적으로" | "지속적으로 모니터링" | 주기 미정 |
| "관련 팀", "유관 부서" | "관련 팀과 협의" | 책임자 미지정 |

### 개선 제안 패턴

```
❌ "성능을 적절히 개선한다"
✅ "응답 시간을 현재 3초에서 1초 이하로 개선한다"

❌ "필요 시 인력을 추가 투입한다"
✅ "2주 연속 일정 지연 발생 시 PM이 추가 인력 투입 여부를 결정한다"

❌ "결제, 정산 등을 처리한다"
✅ "결제(신용카드, 간편결제), 정산(일정산, 정기정산)을 처리한다. 환불·취소는 Out-of-scope"
```

## 유형 2. 구조적 불일치 (Consistency Gaps)

### 범위 ↔ 일정 불일치

**탐지 방법**: 범위 내 주요 기능과 마일스톤을 대조

| 증상 | 예시 |
|------|------|
| 범위에 언급된 기능이 마일스톤에 없음 | 범위: "API 연동", 마일스톤: 연동 일정 없음 |
| 마일스톤이 있으나 담당 범위 명시 없음 | "1차 오픈: 3월" — 무엇을 오픈하는지 없음 |

### 범위 ↔ 인력 불일치

**탐지 방법**: 기능 규모 대비 투입 인력 적정성 판단

| 증상 | 예시 |
|------|------|
| 범위 대비 인력 과소 | 시스템 3개 구축 + 개발자 1명 |
| 전문 인력 누락 | 보안 요구사항 있으나 보안 담당자 없음 |
| 외부 의존 있으나 담당자 미지정 | "외부 API 연동" — 연동 담당자 없음 |

### 일정 ↔ 예산 불일치

| 증상 | 예시 |
|------|------|
| 인력 투입 기간과 예산 불일치 | 3개월 프로젝트 + 6개월 인건비 책정 |
| 외부 용역비 누락 | 외주 개발 예정이나 외주비 예산 없음 |

### 전제조건 ↔ 리스크 불일치

| 증상 | 예시 |
|------|------|
| 전제조건 실패 시나리오가 리스크 없음 | 전제: "3월에 인프라 준비 완료" — 지연 리스크 없음 |
| 리스크 대응책이 전제조건과 모순 | 대응: "서버 증설" — 예산엔 서버 비용 없음 |

## 유형 3. 실행 불가능한 계획 (Unrealistic Planning)

### 일정 비현실성

| 패턴 | 판단 기준 |
|------|---------|
| 요구사항 분석 없이 바로 개발 | 착수 후 1주일 내 개발 시작은 의심 |
| 테스트 기간 없음 | 개발 완료 = 오픈으로 기술된 경우 |
| 병렬 불가 작업이 병렬 계획 | 설계 완료 전 개발 착수 |
| 공휴일·명절 미반영 | 분기말, 설/추석 기간 일정 검토 |

### 리스크 대응 불가능

| 패턴 | 예시 |
|------|------|
| 예산 없이 대응책 | "추가 서버 투입" — 예산 여유 없음 |
| 인력 없이 대응책 | "전문가 긴급 투입" — 인력 풀 없음 |
| 외부 의존 대응책 | "벤더에 긴급 요청" — SLA 없음 |

## 유형 4. 책임 공백 (Accountability Gaps)

### R&R 모호

| 패턴 | 예시 |
|------|------|
| 역할만 있고 사람 없음 | "기획: 미정" |
| 사람만 있고 역할 없음 | "홍길동, 김철수, 이영희" |
| 의사결정자 없음 | 이슈 발생 시 누가 결정하는지 불명확 |
| 발주처/수행사 역할 미구분 | 외주 프로젝트에서 책임 경계 없음 |

### 이해관계자 누락

| 체크 | 누락 시 리스크 |
|------|-------------|
| 최종 사용자 대표 | 요구사항 오해 |
| 보안/컴플라이언스 담당 | 규제 위반 |
| 인프라/운영 담당 | 운영 이관 실패 |
| 재무/구매 담당 | 예산 승인 지연 |

## 유형 5. 성공 기준 부재 (Missing Success Criteria)

| 패턴 | 문제 | 개선 |
|------|------|------|
| "사용자 만족도 향상" | 측정 불가 | "NPS 40점 이상" |
| "시스템 성능 개선" | 기준 없음 | "P95 응답시간 500ms 이하" |
| "안정적인 서비스" | 정의 없음 | "월 가용성 99.5% 이상" |
| "프로젝트 완료" | 완료 기준 없음 | "UAT 통과 + 운영 이관 완료" |
