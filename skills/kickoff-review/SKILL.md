# /kickoff-review — 착수보고서 체크리스트 검토

PMI/PRINCE2 표준 기반 착수보고서를 분석하여 **완성도 점수 + 품질 이슈 + 개선 권고사항**을 제시한다.

## 사용법

```
/kickoff-review @"착수보고서.md"
```

---

## 실행 절차

### Step 1. 문서 읽기

인자로 받은 파일을 전문 읽기. 파일이 없으면 경로를 확인하도록 안내하고 종료.

---

### Step 2. 완성도 체크 (구조 분석)

[references/checklist.md](references/checklist.md)의 9개 섹션을 기준으로 각 필수 항목의 존재 여부와 품질을 판정한다.

각 섹션마다:
1. 문서에서 해당 섹션 내용을 찾는다 (제목이 다를 수 있음 — 내용으로 판단)
2. 필수 항목의 유무와 구체성을 확인한다
3. ✅ / ⚠️ / ❌ 중 하나로 판정한다
4. 판정 근거로 원문을 인용한다

---

### Step 3. 품질 이슈 분석

[references/anti-patterns.md](references/anti-patterns.md)를 기준으로:

**3-1. 모호한 표현 탐지**
- 문서 전체에서 모호 표현 패턴을 찾는다
- 위치(섹션), 원문, 문제점, 개선 제안을 함께 기록한다

**3-2. 일관성 검증**
- 범위 ↔ 일정 불일치 확인
- 범위 ↔ 인력 불일치 확인
- 전제조건 ↔ 리스크 불일치 확인

**3-3. 리스크 평가**
- 식별된 리스크별 대응책 유무 확인
- 문서에 없는 명백한 리스크 제안 (최대 3개)

---

### Step 4. 점수 산출

[references/scoring-rubric.md](references/scoring-rubric.md)의 배점 기준 적용:

1. 섹션별 기본 점수 합산 (✅=100%, ⚠️=50%, ❌=0%)
2. 품질 이슈 감점 적용
3. 보너스 점수 적용
4. 최종 점수 → 등급(A/B/C/D) 결정

---

### Step 5. 결과 출력

아래 형식으로 출력한다:

```markdown
# 착수보고서 검토 결과

**문서**: {파일명}
**검토일**: {오늘 날짜}
**종합 점수**: {등급} ({점수}/100)
**판정**: {등급별 판정 문구}

---

## 1. 완성도 체크

| # | 섹션 | 배점 | 판정 | 획득 | 주요 근거 |
|---|------|------|------|------|---------|
| 1 | 프로젝트 개요 | 15 | ✅/⚠️/❌ | 15/7/0 | "..." (원문 인용) |
| 2 | 범위 정의 | 15 | | | |
| 3 | 일정·마일스톤 | 15 | | | |
| 4 | 조직·R&R | 10 | | | |
| 5 | 예산·자원 | 10 | | | |
| 6 | 리스크·대응 | 15 | | | |
| 7 | 전제/제약 | 10 | | | |
| 8 | 성공 기준 | 10 | | | |
| | **소계** | **100** | | **{합계}** | |

---

## 2. 품질 이슈

### 모호한 표현 ({n}건)

| 위치 | 원문 | 문제 | 개선 제안 |
|------|------|------|----------|
| {섹션명} | "{원문}" | {문제 설명} | {구체적 개선안} |

### 일관성 불일치 ({n}건)

| 항목 A | 항목 B | 불일치 내용 | 권고 |
|--------|--------|------------|------|

### 리스크 평가

**식별된 리스크**:
| 리스크 | 대응책 | 판정 |
|--------|--------|------|
| {리스크} | 있음/없음 | ✅/❌ |

**추가 검토 권장 리스크** (문서 미포함):
1. {리스크 1} — {이유}
2. {리스크 2} — {이유}

---

## 3. 감점/보너스

| 항목 | 점수 |
|------|------|
| 기본 점수 | +{합계} |
| {감점 사유} | -{감점} |
| {보너스 사유} | +{보너스} |
| **최종 점수** | **{최종}** |

---

## 4. 개선 권고사항 (우선순위순)

### 높음 — 착수 전 반드시 해결

| # | 권고 | 대상 섹션 | 이유 |
|---|------|---------|------|

### 중간 — 1차 마일스톤 전까지

| # | 권고 | 대상 섹션 | 이유 |
|---|------|---------|------|

### 낮음 — 진행하며 보완

| # | 권고 | 대상 섹션 | 이유 |
|---|------|---------|------|
```

---

### Step 6. 저장 (선택)

사용자가 저장을 원하면:
- 문서와 같은 디렉토리에 `kickoff-review-{YYYY-MM-DD}.md`로 저장
- 저장 전 확인 요청

---

## 판정 원칙

- **문서에 없는 내용을 있다고 판정하지 않는다** — 모든 ✅는 원문 인용 필수
- **섹션 제목이 달라도 내용으로 판단한다** — "1.1 배경" 대신 "추진 배경" 등 다양한 형식 허용
- **문화적 맥락 고려** — 한국 IT 프로젝트 특성 (발주처/수행사 구조, 공공/민간 구분 등) 반영
- **실행 가능한 권고** — "보완 필요" 대신 "○○ 섹션에 △△ 추가 필요"로 서술
